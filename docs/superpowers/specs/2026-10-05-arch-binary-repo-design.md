# EqualizerAPO — Arch Linux Binary Repository Design

**Date:** 2026-10-05
**Status:** Approved (design) — pending implementation
**Scope:** A self-hosted pacman binary repository for the Linux port, built
and published from this repository's own CI. Windows build untouched.

## 1. Goal

Let an Arch Linux user install and upgrade the Linux port with the normal
package manager:

```
pacman -Sy equalizerapo64
```

The package must build reproducibly on Arch from this repo, install the
host/editor/null tools and systemd user unit correctly, and be servable as a
signed pacman repository from GitHub Releases — no AUR helper, no manual
`cmake --install`.

## 2. Non-goals

- No AUR submission in this effort (a future `-git` PKGBUILD could reuse
  §5).
- No repo hosting in this effort for distros other than Arch.
- No changes to the Windows build, source filters, or config format.
- No auto-enabling of the user service; the user enables it.
- No package history/rollback repo — the hosted repo tracks the latest build
  only (see §7).

## 3. Decisions (locked)

| Decision | Choice |
|---|---|
| Host | GitHub Releases, rolling prerelease tag `arch-repo` |
| Package name | `equalizerapo64` |
| Versioning | `1.4.2.r<commit-count>.g<hash>` (git snapshot of `main`) |
| muparserx | Vendored statically from the pinned fork via CMake `FetchContent` |
| Source of build | The checked-out repo containing the PKGBUILD (not a re-clone) |
| Signing | Dedicated GPG key; CI signs DB + packages (fallback: unsigned) |
| CI | New `.github/workflows/arch-repo.yml`, `archlinux:latest` container |
| Client | Manual `[equalizerapo64]` stanza in `pacman.conf` |

## 4. Repository layout (files added)

```
packaging/arch/PKGBUILD             # builds the binary package from the checkout
packaging/arch/.SRCINFO             # generated by makepkg --printsrcinfo
.github/workflows/arch-repo.yml     # build → sign → repo-add → publish
docs/arch-repo.md                   # end-user install / upgrade / remove
```

Nothing under `EqualizerAPO/`, `Editor/`, or any `.vcxproj`/`.sln`/`.bat`
changes. The `windows_untouched` test must stay green.

## 5. Package (PKGBUILD)

**Metadata**

| Field | Value |
|---|---|
| `pkgname` | `equalizerapo64` |
| `pkgver` | `1.4.2.r<count>.g<hash>` from `version.h` + `git rev-list --count` |
| `pkgrel` | `1` |
| `arch` | `x86_64` |
| `license` | `GPL-2.0-or-later` |
| `depends` | `fftw libsndfile pipewire qt6-base` |
| `optdepends` | `wireplumber` (loudness `wpctl`), `yabridge` (Windows VST2) |
| `makedepends` | `cmake pkgconf git` |

**Source.** The app is built from the checkout that contains
`packaging/arch/PKGBUILD`; `build()` populates `$srcdir/equalizerapo64` by
copying the working tree (`"$startdir/../.."`) while excluding `build*/`,
`.git/`, `.github/` and `packaging/`, so local and CI builds are identical
and no commit/push dance is needed. `muparserx` is the only fetched source:

```
source=("muparserx::git+https://github.com/thefirekahuna/muparserx.git#commit=0a48779615103ca5baa301be9eefecdf23156ec6")
```

**build()**

```
cmake -B build -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_INSTALL_PREFIX=/usr \
  -DFETCHCONTENT_SOURCE_DIR_MUPARSERX="$srcdir/muparserx" \
  -DFETCHCONTENT_FULLY_DISCONNECTED=ON
cmake --build build -j"$(( $(nproc) / 2 + 2 ))"   # half the cores + 2
```

`FETCHCONTENT_FULLY_DISCONNECTED` guarantees no network during build; the
pinned wide-string fork is used, avoiding the ABI mismatch with the AUR
`muparserx` (which is not built wide-string). If the fork's `install()`
rules leak files, add its disable flag or `EXCLUDE_FROM_ALL` (verified at
implementation).

**package()**

1. `cmake --install build` (installs `eqapo-host`, `eqapo-editor`,
   `eqapo-null` into `/usr/bin`, desktop entry into `/usr/share/applications`).
2. Install the systemd unit to `/usr/lib/systemd/user/eqapo-host.service`
   with `ExecStart=/usr/bin/eqapo-host` (`sed` the repo's `/usr/local/bin`
   default), instead of the source tree's `share/equalizerapo/` location.
3. Install `License.txt` to `/usr/share/licenses/equalizerapo64/`.

**check()** runs only the audio-server-free tests (`platform`, `strings`,
`engine_preamp`, `filters`, `null_e2e`, `vst_e2e`, `full_chain_e2e`,
`device_e2e`, `logging_e2e`, `dsp_e2e`, `relative_e2e`, `conv_e2e`). The
`host_e2e`/`reload_e2e` tests need a live PipeWire and are skipped in the
package build.

## 6. CI workflow

`.github/workflows/arch-repo.yml`, triggers on push to `main` and
`workflow_dispatch`:

1. Start `archlinux:latest`; create a non-root `builder` user
   (`makepkg` refuses root); install `base-devel` + deps + `pacman-contrib`.
2. `makepkg -f --nodeps --noconfirm` in `packaging/arch/` (as `builder`).
3. If signing is enabled: import `GPG_PRIVATE_KEY` into a temp `GNUPGHOME`,
   run `repo-add --sign`.
4. Delete all assets on the `arch-repo` release, then upload the fresh
   `.pkg.tar.zst`, `equalizerapo64.db`, `equalizerapo64.db.tar.gz`,
   `equalizerapo64.files`, `equalizerapo64.files.tar.gz` and their `.sig`s
   (creating the release if absent). Deleting first avoids stale package
   filenames accumulating.

## 7. Hosting and client config

The `arch-repo` release is a dedicated tag (marked prerelease) so it never
collides with the Windows installer releases or GitHub's `latest`. Users add:

```
[equalizerapo64]
SigLevel = Required DatabaseRequired
Server = https://github.com/gustavomgama/equalizerAPO64/releases/download/arch-repo
```

pacman requests `Server/equalizerapo64.db` and package filenames; GitHub
302-redirects to the asset store and libcurl follows. The repo holds only the
latest build: upgrading replaces the DB and package asset.

## 8. Signing

- A dedicated GPG key (separate from any personal key).
- CI secrets: `GPG_PRIVATE_KEY` (armored) and `GPG_KEY_ID`.
- Public key published as a release asset; users import once with
  `sudo pacman-key --add equalizerapo64.asc && sudo pacman-key --lsign-key <id>`.
- Fallback if no key is wanted now: unsigned repo with
  `SigLevel = Optional TrustAll` — explicitly insecure, documented as such.

## 9. Verification

1. Local: `makepkg -f` succeeds on this Arch machine; the `.pkg.tar.zst`
   installs `eqapo-host`/`eqapo-editor`/`eqapo-null` to `/usr/bin` and the
   unit to `/usr/lib/systemd/user/` with `ExecStart=/usr/bin/eqapo-host`.
2. Local: `repo-add` produces the DB; `pacman -Sy` against a local
   `file://` repo lists `equalizerapo64`; `pacman -S` installs it.
3. `ctest` suite still green (including `windows_untouched`).
4. CI: a `workflow_dispatch` run publishes assets; `pacman -Sy` against the
   GitHub URL sees the package.

## 10. Risks

| Risk | Mitigation |
|---|---|
| muparserx fork install rules pollute `/usr` | Verify; pass its install-off flag / `EXCLUDE_FROM_ALL` |
| `makepkg` runs as root in the container | Build as a non-root `builder` user |
| GitHub asset URLs change under a release | Fixed tag + fixed asset names, delete-then-upload |
| Unsigned fallback is insecure | Default to signing; fallback documented as insecure |
| Version drift (`version.h` stays 1.4.2 across Linux work) | `r<count>.g<hash>` suffix makes every build unique |
